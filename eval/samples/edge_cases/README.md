# 异常用例（不计入 8/10）

这些用例检验输入预处理和错误处理，**不计入** 10 条正样的 8/10 验收。期望全部依据 `/workspace/dev-task-splitter-arch-v1.md`：第 3.2 节「校验策略」和文末变更记录（2026-11-20）。文档没写具体文案的地方一律写「以实现为准」，只记录实际文案，不另编。

## 已定规则

- **长度**：去掉首尾空白后按字符数计（`len(s.strip())`，汉字、英文、标点、中间的换行都算 1 个字符）。≤3000 放行，3001 起直接拒绝，**不截断**。这一步在调用前做，不调接口。
- **空输入**：去首尾空白后为空，直接拦截，不调接口。
- **时限**：单次调用超时默认 60 秒，是配置项。不触发重试时，单条 60 秒内出结果。
- **重试**：所有重试都**只有 1 次**，按失败类型区分：

| 失败类型 | 是否重试 | 期望接口调用次数 | 重试方式 |
|---|---|---|---|
| 空输入 / 超长（>3000） | 不调接口 | 0 | — |
| 没有 API key | 不重试 | 0（发请求前直接提示配置问题） | — |
| 401 / 403 | 不重试 | 1 | — |
| 超时 | 重试 1 次 | 2 | 原样重发 |
| 5xx / 网络错误 | 重试 1 次 | 2 | 原样重发 |
| JSON 解析失败（含空内容）/ 校验失败（含条数超限）/ `finish_reason == "length"` 截断 | 重试 1 次 | 2 | 把错误信息回传给模型，要求重新输出完整 JSON |
| 429 限流 | 重试 1 次 | 2 | 等 2 秒再重试；仍失败显示「请求太频繁（已重试 1 次），请稍后再试。」 |

- **重试用尽**：UI 显示错误（JSON 失败时附原始输出），页面不崩溃，不把失败结果当成功渲染。
- **评审口径**（产品经理确认）：触发了重试的，评审表「≤60s」填「不适用」，重试次数必须 ≤1。A 情形（重试后成功）按普通样例评内容：任务和测试点各至少 1 条、不串类、unclear 时问题非空。B 情形（重试后仍失败）检查界面显示的是不是对应的错误文案：超时、5xx/网络错误以实现为准，429 为「请求太频繁（已重试 1 次），请稍后再试。」。正样在真实运行中重试后仍失败的，记不合格。
- 所有用例的错误信息里都不能出现 API key。

除 429 外，其它提示文案都**以实现为准**，评审时把实际文案记在评审表里。

调用次数怎么数：看 `llm_client` 的日志或 mock 的调用计数。「重试次数」= 调用次数 − 1（不调接口时记 0）。

## E01 空输入

- **触发方式**：输入框不填，直接点拆解；或粘贴 `E01_empty_input.txt`。
- **期望调用次数**：0（重试 0）。
- **期望表现**：预处理拦截，提示需要输入（文案以实现为准），不展示空白三块，页面不崩溃。

## E01b 仅空白字符

- **触发方式**：粘贴 `E01b_whitespace_only.txt`（空格、换行、Tab）。
- **期望调用次数**：0（重试 0）。
- **期望表现**：去首尾空白后为空，按 E01 处理。

## E02 接近上限的合法输入（2984 字符）

- **文件**：`E02_long_about_3000.txt`，`len(s.strip())` = **2984**（汉字 1974，来自 C06 的商品评论邮件串，夹了很多跑题闲聊）。
- **期望调用次数**：1（不触发重试时）。
- **期望表现**：≤3000，放行并完整拆解，不截断。不触发重试时 60 秒内出结果；记录实际耗时，并检查 JSON 有没有被截断。

## E03 明显超限

- **文件**：`E03_long_over_limit.txt`，`len(s.strip())` = **6288**（汉字 4454）。
- **期望调用次数**：0（重试 0）。
- **期望表现**：预处理直接拒绝，不截断、不送进模型；提示超出长度上限（文案以实现为准），页面不崩溃。

## E07 精确 3000 字符（边界内）

- **文件**：`E07_boundary_3000_chars.txt` = E02 正文 + 一句补充。补充句是截出来凑长度的，句子不完整，不影响拆解。文件没有末尾换行，`len(s.strip())` = **3000**。
- **期望调用次数**：1（不触发重试时）。
- **期望表现**：放行（3000 允许），正常拆解，不截断。

## E08 精确 3001 字符（边界外）

- **文件**：`E08_boundary_3001_chars.txt`，比 E07 多 1 个字符，`len(s.strip())` = **3001**。
- **期望调用次数**：0（重试 0）。
- **期望表现**：拒绝（3001 不允许），不截断成 3000 后再调用，提示超长（文案以实现为准）。

校验方法：

```bash
python3 -c "import sys;[print(f, len(open(f,encoding='utf-8').read().strip())) for f in sys.argv[1:]]" E0*.txt
```

## E04 没有 API key

- **触发方式**：不创建 `.env`，或把 `DEEPSEEK_API_KEY` 置空/删除后启动，粘贴 S01 点拆解。不要把真实 key 写进任何文件。
- **期望调用次数**：0（重试 0）。
- **期望表现**：不重试，直接提示配置问题（文案以实现为准）；页面不崩溃；错误信息不泄露任何密钥。

## E09 401 / 403（错误 key）

- **触发方式**：把 `DEEPSEEK_API_KEY` 设成无效值（如 `sk-invalid-test`），或 mock 接口返回 401 / 403，两种状态码各测一次。
- **期望调用次数**：1（重试 0）。
- **期望表现**：不重试，直接提示 key 或权限配置问题（文案以实现为准）；页面不崩溃。

## E05 接口超时

- **触发方式**：超时默认 60 秒，是配置项。测试时把它调短（如 1 秒），或用 mock / 代理让请求挂起。
  - A：第 1 次超时，第 2 次返回合法结果；
  - B：两次都超时。
- **期望调用次数**：2（重试 1），原样重发，不再多重试。
- **期望表现**：A 正常展示三块；B 展示错误（文案以实现为准），不把空结果当成功，页面不崩溃。

## E11 5xx / 网络错误

- **触发方式**：mock 接口返回 503（也可测 500/502）；或在测试环境断网 / 让 DNS 解析失败。
  - A：第 1 次 503，第 2 次成功；
  - B：两次都失败。
- **期望调用次数**：2（重试 1），原样重发。
- **期望表现**：A 正常展示；B 展示错误（文案以实现为准），页面不崩溃。

## E06 JSON 解析失败

- **触发方式**：mock LLM，不依赖线上偶发。返回 `json.loads` 解析不了的内容：纯散文、截断的 JSON 或空内容。
  - A：第 1 次非法，第 2 次合法；
  - B：两次都非法；
  - C（可选）：能 `json.loads`，但 pydantic 或业务校验不通过，比如缺字段、非法枚举、条数超限（`tasks` > 10、`test_points` > 20、`questions` > 8、`steps` > 5），或 `input_type` 为 `unclear` 而 `questions` 为空。走同一条重试路径。
  - D：响应的 `finish_reason == "length"`（输出被截断）。按 JSON 失败处理，重试 1 次；即使截断后的内容碰巧能 `json.loads`，也不能当成功。可以同样分 A/B 两种结果来测。
- **期望调用次数**：2（重试 1）。第 2 次请求要追加一条 user 消息，带上错误信息，要求重新输出完整 JSON。
- **期望表现**：A 正常展示；B 展示错误 + 原始输出，不崩溃，不假装成功（文案以实现为准）。

## E10 429 限流

- **触发方式**：mock 接口返回 HTTP 429。
  - A：第 1 次 429，第 2 次成功；
  - B：两次都 429。
- **期望调用次数**：2（重试 1），两次调用之间至少隔 2 秒。
- **期望表现**：A 正常展示；B 显示的文案**必须一字不差**：

  > 请求太频繁（已重试 1 次），请稍后再试。
