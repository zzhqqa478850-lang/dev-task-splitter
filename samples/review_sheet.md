# 评审表（10 条正样 + 额外注入用例 + 异常用例）

- 产品：dev-task-splitter（杂乱需求/bug → 任务、测试点、待澄清问题）
- 评审日期：__________　　评审人：__________　　构建/提交：__________　　模型：__________　　超时配置：____ 秒（默认 60）
- 合格标准（同时满足才算合格）：
  1. 不触发重试时 ≤60 秒出结果；重试次数必须 ≤1；
     - 触发了重试的样例：「≤60s」填「不适用」，「重试结果」填 `成功` 或 `仍失败`；
     - **重试后成功**：按普通样例评内容，看下面 2–5 条；
     - **重试后仍失败**：没有内容可评，该条记**不合格**（计入 8/10 的分母）。另外检查界面显示的是不是对应的错误文案，填进「仍失败时错误文案正确」列：超时、5xx/网络错误的文案以实现为准，429 必须一字不差为「请求太频繁（已重试 1 次），请稍后再试。」；
  2. 任务、测试点各至少 1 条；
  3. 问题块默认可以为空，只有 `input_type == "unclear"` 时必须非空；
  4. 三块不串类；
  5. S04 还要通过模糊断言：`input_type == "unclear"`、至少 1 个任务的 `category == "clarification"`、`questions` 非空。
- 集合验收线：**合格数 ≥ 8/10**。X01 和异常用例不计入这 10 条。

填写说明：「实际耗时(秒)」填秒数（如 `12.4`）；「重试次数」填 0 或 1（看日志）；「重试结果」填 `无重试`、`成功` 或 `仍失败`；「仍失败时错误文案正确」只在重试结果为 `仍失败` 时填 `是/否`，并把实际文案抄进备注，其余情况填 `不适用`；其余判定列填 `是`、`否` 或 `不适用`。「问题块」列：`input_type` 不是 `unclear` 时填 `不适用`。
