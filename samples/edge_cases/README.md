# 异常用例（不计入 8/10）

这些用例检验预处理和错误处理，**不计入** 10 条正样的 8/10 验收。期望表现优先依据架构草案 v1 的错误处理设计；文档没写清的已标 **待确认**，并给出建议行为，需产品经理/开发拍板后再变成硬性验收。

架构中已写明的相关设计：

- 预处理：去空白 / 长度检查。输入长度建议上限「如 ≤ 3000 字」（计数口径未定义，见 E02/E03）。
- DeepSeek 调用后：`json.loads` 失败，或 pydantic / 引用检查失败 → 把错误信息回传给模型重试，**最多 2 次**（加首次共最多 3 次尝试）。JSON 模式偶发返回空内容也按失败重试。
- 重试用尽：界面展示错误 + 原始输出，**不崩溃**。
- `llm_client` 需封装超时，但未规定秒数、超时是否走上述重试、以及 UI 文案。
- API key 来自 `.env` 的 `DEEPSEEK_API_KEY`，未规定缺失时的启动/点击行为。

「字」在实现里可能是 `len(文本)`（含标点、英文、空白）或仅统计汉字。下面两条超长文本同时给出**总字符数**和**汉字数**，便于对照两种口径。

## E01 空输入

- **触发方式**：在输入框中不粘贴任何内容，直接点击拆解。也可使用本目录 `E01_empty_input.txt`（空文件）。
- **期望表现**：**待确认**（架构只写了去空白/长度检查，未写空输入是否拦截、是否调用模型、提示文案）。
- **建议**：预处理阶段拦截，不调用 DeepSeek，界面明确提示「请粘贴需求或缺陷描述」，页面不崩溃、不展示空白三块假成功。

## E01b 仅空白字符

- **触发方式**：粘贴 `E01b_whitespace_only.txt`（仅空格、换行、Tab），或手工只输入空格后提交。
- **期望表现**：**待确认**。
- **建议**：去空白后按 E01 空输入处理，不要把空白送进模型。

## E02 约 3000 字输入

- **文件**：`E02_long_about_3000.txt`
- **规模**：2984 个字符，其中汉字 1974 个（来自全量评测集 C06：商品评论邮件转发串，含大量跑题闲聊）。
- **触发方式**：将该文件全文粘贴进输入框并提交。
- **期望表现**：**待确认**计数口径和边界（3000 含不含等于）。
  - 若上限按**总字符**且为 ≤ 3000：本条为接近上限的合法输入，应尝试完整拆解，并观察是否仍在 30 秒内返回、JSON 是否被截断。
  - 若上限按**汉字**且为 ≤ 3000：本条汉字仅 1974，应视为未超限。
- 本文件本身是有效需求文本，不要只测长度；若系统接受输入，三块仍应尽量可评。

## E03 明显超限输入

- **文件**：`E03_long_over_limit.txt`
- **规模**：6289 个字符，其中汉字 4454 个（把积分商城群聊与商品评论邮件串合并，并加了说明头尾，两种口径都明显超过 3000）。
- **触发方式**：将该文件全文粘贴并提交。
- **期望表现**：**待确认**超限后是拒绝提交、截断后调用，还是原样送进模型。
- **建议**：在预处理阶段拦截并提示超过长度上限（同时展示上限与当前长度），不要把全文送进模型以免超 `max_tokens` 或产生不可控费用；页面不崩溃。若产品决定截断后仍拆解，应明确告知用户已截断。

## E04 没有 API key

- **触发方式**（实现后）：不要创建 `.env`，或把 `DEEPSEEK_API_KEY` 留空/删除后再启动应用并尝试拆解（可用任一条正样，如 S01）。不要把真实密钥写入本仓库。
- **期望表现**：**待确认**（架构只要求从环境读取 key，未写缺失时的 UX）。
- **建议**：在启动或点击拆解时即明确提示缺少 `DEEPSEEK_API_KEY`，不向网络发起无效请求，进程和页面不崩溃；错误信息中不要打印其它环境密钥。

## E05 接口超时

- **触发方式**（实现后，任选其一道，需在测试环境进行）：
  1. 将客户端超时调到极短（例如 1 秒）再提交一条正样；
  2. 用 mock / 代理让 `api.deepseek.com` 请求挂起直到超时。
- **期望表现**：**待确认**超时时长默认值、超时是否计入「最多 2 次重试」、以及界面文案。
- **建议**：向用户展示可理解的超时/网络失败提示，允许重试；不要把半截或空响应渲染成成功的三块结果；页面不崩溃。

## E06 JSON 解析失败

- **触发方式**（实现后，需 mock LLM，不要依赖线上偶发）：让模型返回无法 `json.loads` 的文本（纯散文、截断的 JSON、或空内容）。也可另外测一次 pydantic 校验失败（缺字段、非法枚举、非法 id）。
- **期望表现**（架构已写明，可作为硬性检查）：
  1. 将错误信息回传，要求模型「修正后重新输出完整 JSON」；
  2. 最多重试 2 次；空内容同样重试；
  3. 仍失败则在 UI **展示错误 + 原始输出**，不崩溃，不假装成功。
